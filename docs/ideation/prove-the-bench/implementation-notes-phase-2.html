Implementation Notes — Phase 2

prove-the-bench · 2026-09-24 · Graded checks and SDK recall

Stale rebuild — rebuild on any schema mismatch

Context
Spec says rebuild when stored.schema_version !== REPORT_SCHEMA_VERSION; the old resolveReport comment promised to preserve fields a newer producer may add.
Decision
Followed the spec literally (!==), so a newer stored report is rebuilt at the current schema; updated the comment to say the bundled UI reads the shape it knows. For a stale report with cost_estimate, its pricing snapshot is reused (spec Failure Modes). The verbatim-embed test marker now carries the current schema_version.
Alternative
Rebuild only when older or missing (<), keeping forward-compat verbatim copying.

Diagnose — ungraded checks excluded from failedChecks

Context
Spec is silent; src/diagnose/select.ts lists every check with passed < total as a failed check, so seeded docs/cli pairs would feed sdk-wired misses into diagnosis prompts as failures.
Decision
Filter graded !== false in failedChecks (one predicate, tested in graded-checks). Ungraded checks never enter pass/fail, so they should not be presented as failure evidence.
Alternative
Leave select.ts untouched and accept the leakage.

Report UI — new SDK recall card

Context
Spec mentions an "experiments card" in Report.tsx; none exists.
Decision
Added a card modelled on the surface-usage card (testid sdk-recall), one row per experiment reading SDK recall r/a or n/a (absent field in older snapshots, or null rate). Added a tiny .tag CSS class.
Alternative
A column in the pairs table (recall is per experiment, not per pair).

E2E — graded-only count asserted as 9/9

Context
Spec example says 3/3 checks, but the Heatmap sub-text sums checks across a pair's completed trials.
Decision
Asserted 9/9 checks on the sweep run's auth-nextjs × claude-docs cell (3 trials × 3 graded; 9/12 if ungraded were counted), plus the ungraded tag in its drill-down and in the report pairs table.
Alternative
Seeding a one-trial cell to get a literal 3/3.

Validation — dev-data drift check vs unstaged changes

Context
The spec's git diff --quiet -- ui/dev-data check assumes regenerated data is already committed; this build must leave all changes unstaged, so the command cannot pass until the commit stage lands the regenerated files.
Decision
Regenerated dev data, then regenerated again and diff -r'd the two trees: identical (deterministic, no drift). New snapshot directories are registered with git add -N.
Alternative
Staging dev-data to satisfy the literal command (forbidden by the engine overrides).

ReportCheck.graded — required in the type, tolerant at read

Context
Spec declares graded: boolean as required; older hosted report snapshots lack it.
Decision
Kept it required on the TS type (the builder always sets it), documented absence in schema < 7, and every reader uses graded !== false so absence reads as graded. ReportExperiment.sdk_recall is optional on the wire with the same note.
Alternative
Making graded optional in the type.

Docs — example check name is snake_case

Context
Seed data uses kebab-case sdk-wired; writing-an-eval.md tells authors to use stable snake_case names.
Decision
The doc example uses sdk_wired to match the doc's own naming rule; seed data keeps sdk-wired per spec.
Alternative
Using kebab-case in the doc against its own convention.
