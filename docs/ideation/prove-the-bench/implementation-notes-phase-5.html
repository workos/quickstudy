Implementation Notes — Phase 5

prove-the-bench · 2026-09-24 · Per-experiment leaderboard

Added discriminating passed/scored counts

Context
The spec's ExperimentAggregate has only rates, but the pass cell renders 11/17 · 6/6.
Decision
Added discriminating_passed and discriminating_scored. discriminating_evals counts distinct benchmark evals with band discriminating where this experiment scored at least one attempt.
Alternative
Render percentages instead of counts.

Benchmark filter applies to every aggregate field

Context
The spec says the pass rate is over benchmark pairs, but it is silent on counts, time, tokens and cost.
Decision
Every field (counts, median, tokens, cost, estimated) uses benchmark-suite attempts only, so one attempts denominator covers the whole row. SDK recall stays all-suite (the existing Phase 2 value). Documented in docs/concepts.md.
Alternative
Filter only the pass rates, which would mix denominators within a row.

Cost/run shows the mean per reporting attempt

Context
The column header is "Cost/run", but the example $1.99 · 12/17 reported is ambiguous between a total and a mean.
Decision
The UI shows cost_usd / cost_attempts (and the estimated mean) per run. The text renderer shows the total with its counts, matching the run-wide telemetry line.
Alternative
Show the total cost in the UI cell.

Comparator lives in aggregate.ts

Context
The UI needs the sort, but report.ts imports node:fs. A runtime import from it would pull Node modules into the Vite bundle.
Decision
compareLeaderboard lives in src/report/aggregate.ts, which has only type imports. report.ts re-exports it.
Alternative
Duplicate the sort in the UI.

e2e asserts "reported", not "not reported"

Context
The spec's playground says codex rows read not reported, but the seed gives every completed attempt costUsd: 0.11, and invariants-v3 pins that value.
Decision
The e2e asserts 9/9 reported / 8/9 reported. The unit tests cover null cost (cost_attempts: 0) and the text renderer covers not reported (0/N).
Alternative
Change the seed costs, which would break the pinned invariants.

fmtTokens changed in place

Context
fmtTokens already existed and printed 512.0k.
Decision
A trailing .0 is now stripped (512k, 1M), and fractional values below 1000 round (means can be fractional). The existing cases still pass.
Alternative
Add a second formatter.

The dev-data validation command conflicts with the unstaged-diff rule

Context
git diff --quiet -- ui/dev-data && test -z "$(git status --porcelain -- ui/dev-data)" can only pass once regenerated dev data is committed. The workflow requires leaving changes unstaged.
Decision
Verified determinism instead: hashed every file after one regeneration, regenerated again, and got identical hashes.
Alternative
Stage or commit the dev data, which the engine forbids.
