Error-kind classification — container provision keeps its return

Context
Spec step 2 says to wrap the provision block and throw new StageFailure("environment", e).
Decision
The provision catch already runs a teardown and returns an error disposition; it now returns errorKind: "environment" instead. The container IIFE catch (which the spec does not mention) also maps errorKindOf(err), since every in-IIFE StageFailure lands there, not in the outer loop.
Alternative
Throwing from the provision catch would skip the existing teardown-then-return path.

Error-kind classification — inStage helper and exported errorKindOf

Context
Spec asks for wrapping each stage boundary with StageFailure, and a unit test of the outer mapping with a bare Error.
Decision
Added a tiny inStage(kind, fn) wrapper (preserves an inner StageFailure) and exported StageFailure + errorKindOf so the harness mapping is unit-testable. Host adapter throws are re-thrown as StageFailure("agent") so the outer catch keeps writing the error artifact.
Alternative
Inline try/catch at every site; returning a disposition directly from the host catch (would duplicate the writeError call).

UI badges — timedOut KPI vs incomplete banner

Context
Spec: timedOut count includes graded timeouts. It was only consumed by incompleteReason, which would then blame graded (complete) timeouts for an incomplete run.
Decision
Kept totals.timedOut per spec and rendered it as a gray “N timed out” KPI badge when > 0; the banner now gets a separate unscoredTimedOut (legacy incomplete timeouts only).
Alternative
Passing the inflated count to the banner (misleading; negative otherIncomplete).

Existing tests and docs flipped by the new timeout semantics

Context
Spec lists neither the runner/docker tests that asserted incomplete on timeout nor docs/extensions.md / docs/publishing-a-benchmark.md.
Decision
Updated those assertions to completed + limitHit: "timeout". The retry test now produces its unfinished row with an adapter throw (error) since timeouts are no longer unfinished. Docker-gated tests were edited but could not run locally (no daemon). Fixed the two contradicting doc sentences.
Alternative
Leaving stale docs/tests.

Error-kind tests — unpreparable local/ fixture

Context
Spec experiment (c): an eval whose localDir points at a missing path. The run manifest hashes localDir before any attempt, so a missing path aborts the whole run.
Decision
Used a local/ with a chmod-000 node_modules dir: the identity hash skips it, the workspace copy cannot read it → environment. Skipped when running as root.
Alternative
A getter/stack hack on localDir.

Validation — dev-data git-clean check

Context
The command bun run ui:dev-data && git diff --quiet -- ui/dev-data can only pass once the regenerated data is committed; this stage must not commit.
Decision
Verified the generator is deterministic (two regenerations produce byte-identical trees). The regenerated tree also picks up pre-existing drift at HEAD (run_paths/snapshots/, incomplete flags in meta.json) — all of ui/dev-data must be committed, including the new untracked snapshot dirs.
Alternative
Staging dev-data to satisfy the check (violates the leave-unstaged override).
