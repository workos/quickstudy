prove-the-bench · 2026-09-24 · Scorer health and matrix bands

Scorer health — checks missing from some attempts

Context
The spec says a suspect "failed in every scored attempt" but is silent when a check is absent from some attempts.
Decision
A check is a suspect only when it is present with passed:false in every completed attempt of the arms; a passing check must be present with passed:true in all of them. A name flagged graded:false in any attempt is excluded from both sides (mirrors the pair tally). Tested.
Alternative
Treat absence as failure, which would flag scorers that emit checks conditionally.

Matrix — discriminating header count and band aria-labels

Context
The spec places unbanded (single-arm) rows in the discriminating section with a "(n evals with one scored arm)" suffix, and gives Heatmap an optional band label "for the header".
Decision
The header count includes the unbanded rows, and the suffix names how many of them there are. Counts come from the filtered rows. The band label names each heatmap's region (Pass-rate matrix — {band}), so the three regions have distinct accessible names. <details> stays uncontrolled. The e2e .scroll-hint assertion now uses .first(), since there is one hint per heatmap.
Alternative
Count only discriminating rows in the header, or render a visible heading inside Heatmap.

Seed data — new evals use framework "generic"

Context
The cell-states run needs uniform-pass and uniform-fail in its manifest and config.evalIds, or coverage and metadata break.
Decision
Added CELL_STATE_EVALS (the seed evals plus the two new ones, with framework generic), 3 trials × 2 arms each, and a per-spec checks override. This adds a generic option to the framework filter on that run. No e2e test enumerates the filter options.
Alternative
Reuse an existing framework such as nextjs, which would mix the new evals into that framework's filter.

Validation — the dev-data cleanliness check needs a commit first

Context
The spec's bun run ui:dev-data && git diff --quiet -- ui/dev-data && test -z "$(git status --porcelain -- ui/dev-data)" compares the output against the committed tree. This phase intentionally changes dev data, and the engine forbids committing here.
Decision
Checked determinism instead: the tree hash of ui/dev-data was identical across two regenerations. The literal command passes once the commit stage lands the regenerated files.
Alternative
Commit the dev data here, which the engine overrides forbid.
